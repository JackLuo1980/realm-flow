## 核心组件

### 1. 前端面板 (vite-frontend/)

**技术栈**:
- React + Vite (rolldown-vite 实验性打包器)
- shadcn-bridge (UI 兼容层)
- Tailwind v4 (CSS)

**入口**: `src/App.tsx`

**特点**:
- H5 模式检测（移动 WebView vs 桌面）
- 语义化颜色主题
- 非压缩构建（便于调试）

### 2. 后端 API (go-backend/)

**技术栈**:
- Go 1.24
- GORM + net/http
- SQLite / PostgreSQL

**入口**: `cmd/paneld/main.go`

**核心模块**:
| 模块 | 路径 | 职责 |
|------|------|------|
| Handler | `internal/http/handler/` | HTTP 请求处理 |
| Repository | `internal/store/repo/` | 数据访问层 (83k LOC) |
| Model | `internal/store/model/` | 数据模型定义 |
| Middleware | `internal/http/middleware/` | JWT/CORS/日志/恢复 |
| WebSocket | `internal/ws/` | 实时通信 |

### 3. 节点代理 (go-gost/)

**技术栈**:
- Go 1.23
- forked GOST v3
- 自定义 x/ 模块替换

**入口**: `main.go`

**核心模块**:
| 模块 | 路径 | 职责 |
|------|------|------|
| 引擎抽象 | `x/socket/forward_engine*.go` | 多引擎适配器 |
| WebSocket | `x/socket/websocket_reporter.go` | 状态上报 |
| 加密 | `x/internal/util/` | AES 加密通信 |

## 数据模型

### 核心实体关系

```
User (用户)
  │
  ├─── Forward (转发) ────▶ Tunnel (隧道)
  │                              │
  └──────────────────────────────┘
                                 │
                                 ▼
                              Node (节点)
```

### Forward 模型关键字段

```go
type Forward struct {
    ID          int    `gorm:"primaryKey"`
    UserID      int    `gorm:"index"`
    UserName    string // ⚠️ 需与 user.user 同步 (BUG-01)
    TunnelID    int
    Name        string `gorm:"index"`
    InPort      int    // 入口端口
    RemoteAddr  string // 目标地址 host:port
    Strategy    string // fifo 等
    Engine      string // gost/nftables/realm
    InFlow      int64  // 入流量
    OutFlow     int64  // 出流量
    // ...
}
```

## 转发引擎架构

### 引擎抽象接口

```go
type ForwardEngine interface {
    Name() string
    DryRun(ctx, req) (*ForwardApplyResult, error)
    Apply(ctx, req) (*ForwardApplyResult, error)
}
```

### 引擎实现

| 引擎 | 类型 | 位置 | 特点 |
|------|------|------|------|
| gost | 用户态 | `forward_engine_gost.go` | 成熟稳定，功能全 |
| nftables | 内核态 | `forward_engine_nftables.go` | 高性能，需 counter |
| realm | 内核态 | `forward_engine_realm.go` | 新型，待完善 |

### 引擎选择流程

```
┌─────────────┐
│ 创建/更新转发 │
└──────┬──────┘
       │
       ▼
┌─────────────────┐
│ 前端选择 engine  │──▶ gost / nftables / realm
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 后端持久化      │──▶ forward.engine 字段
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 下发节点        │──▶ UpdateService {forwarder: {engine: "nftables"}}
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 节点执行        │──▶ 根据引擎选择适配器
└─────────────────┘
```

## 通信协议

### API 响应格式

```json
{
  "code": 0,        // 0 = 成功
  "msg": "success",
  "data": {},
  "ts": 1710931200000
}
```

### 认证方式

```
Authorization: <raw_jwt_token>  // 无 Bearer 前缀！
```

### 节点上报加密

- 算法: AES
- 密钥: 节点 `secret` 作为 PSK
- 用途: 防止未授权节点上报

## 部署架构

### Docker Compose (v4)

```yaml
services:
  backend:
    image: fork-nft-backend:latest
    ports: ["6365:6365"]
    environment:
      - JWT_SECRET=...
  frontend:
    image: fork-nft-frontend:latest
    ports: ["6366:80"]
  db:
    image: postgres:15
```

### 一键部署脚本

- **面板**: `panel_install.sh` → 下载 compose → 生成 JWT_SECRET → 启动
- **节点**: `install.sh` → 下载 binary → 写配置 → systemd 服务

## 流量统计架构

### GOST 模式

```
用户请求 → GOST → 服务
          │
          └─▶ 统计事件 ▶ 上报 /flow/upload
```

### NFT 模式 (BUG-03 修复)

```
用户请求 → DNAT → 服务
              │
              └─▶ nft counter
                      │
                      ▼
            nft-flow-exporter.py (10s 周期)
                      │
                      ▼
                 /flow/upload
```

## PO0 同步流程

```
/etc/relay-forwards.conf (PO0)
         │
         ▼
sync-po0-forwards-to-panel.sh
         │
         ├─── 解析: name|host|target_port|relay_port
         ├─── 映射: inPort=relay_port (BUG-02 修复)
         ├─── 锁定: engine=nftables
         └─── 上报: /api/v1/forward/create|update
```
