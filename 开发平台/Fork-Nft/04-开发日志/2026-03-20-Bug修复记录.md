## BUG-01: 用户名显示旧值（admin_user）

### 问题描述
修改用户名为 `jack` 后，转发卡片区域仍显示 `admin_user`，导致界面用户标识与真实账号不一致。

### 根因分析
仅更新了 `user.user` 字段，未同步历史 `forward.user_name` 字段。

### 修复方案

**修改文件**:
- `go-backend/internal/store/repo/repository.go`
- `go-backend/internal/store/repo/repository_mutations.go`

**核心改动**:
在三个用户更新方法中添加同事务同步 `forward.user_name`：
1. `UpdateUserNameAndPassword` - 更新用户名和密码
2. `UpdateUserWithPassword` - 带密码更新
3. `UpdateUserWithoutPassword` - 不带密码更新

**回归测试**:
```bash
go test ./internal/store/repo -run 'TestUpdateUser(NameAndPassword|WithoutPassword)SyncsForwardUserName' -count=1
```

**测试文件**: `go-backend/internal/store/repo/repository_user_name_sync_test.go`

### 线上验证
已补历史数据，当前 JP-CO/HK-Jinx/Boil HKT 的 userName 已同步为 `jack`。

## BUG-02: 诊断失败（端口映射错位）

### 问题描述
PO0 同步后入口端口/目标端口错位，导致诊断探测错误目标端口，出现"所有 TCP 连接尝试都失败"。

### 根因分析
`scripts/sync-po0-forwards-to-panel.sh` 脚本把 `/etc/relay-forwards.conf` 的字段 `name|host|target_port|relay_port` 错当成 `name|host|in_port|target_port`。

**正确映射应为**:
- `inPort = relay_port` (面板入口端口)
- `remoteAddr = host:target_port` (目标地址)

### 修复方案

**修改文件**: `scripts/sync-po0-forwards-to-panel.sh`

**核心改动**:
```python
# 修复前（错误）
in_port = target_port  # 错误映射
target_port = relay_port

# 修复后（正确）
in_port = relay_port   # 入口端口 = relay 端口
target_port = target_port  # 保持原值
```

**Payload 构建**:
```python
obj = {
    'name': name,
    'tunnelId': int(tunnel_id),
    'inPort': int(relay_port),      # 正确映射
    'remoteAddr': f'{host}:{target_port}',  # 正确映射
    'strategy': 'fifo',
    'engine': 'nftables',
}
```

**回归测试**:
```bash
./tests/scripts/test_sync_po0_forwards.sh
```

### 线上验证
JP-CO 已恢复为正确映射：
- `inPort=31000`
- `remoteAddr=198.176.52.9:55894`
- 诊断返回成功 ✅

## BUG-03: 有流量但监控为 0（nft-only）

### 问题描述
节点实际转发有流量，但面板统计为 0B。

### 根因分析
1. nft DNAT 转发绕过了服务层统计事件，默认不会产生可直接上报的 per-forward 流量
2. 现网 nft 规则未开启 `counter`，无法读取每端口字节数

### 修复方案

#### 1) nft 规则模板加入 counter

**修改文件**: `go-gost/x/socket/forward_engine_nftables.go`

**核心改动**: 生成 DNAT/SNAT 规则时添加 `counter` 关键字，使 nft 记录每个端口的流量统计。

#### 2) 新增 nft 流量导出器

**新增文件**: `scripts/nft-flow-exporter.py`

**功能**:
- 读取 nft chain 的 counter 值（按端口）
- 计算增量（当前值 - 上次值）
- 上报面板 `/flow/upload` API

**核心逻辑**:
```python
# 1. 加载 nft counter
port_bytes = load_nft_chain(family, table, chain)

# 2. 计算增量
current = port_bytes[relay_port]
previous = cache.get(str(relay_port), current)
delta = current - previous

# 3. 上报
items.append({"n": service_name, "u": 0, "d": delta})
upload_flow(base, secret, items)
```

#### 3) 安装脚本

**新增文件**: `scripts/install-nft-flow-exporter.sh`

**功能**:
- 一键安装 systemd timer
- 10s 周期执行流量导出
- 自动配置面板连接

**回归测试**:
```bash
go test ./socket -run 'TestNftablesAdapterRenderIncludesCounters|TestNftablesAdapterApplyBlocksUnintendedShrink' -count=1
python3 -m py_compile scripts/nft-flow-exporter.py
```

### 线上验证
已部署到 PO0：
- ✅ `nft-flow-exporter.timer` 已 active
- ✅ `forward.inFlow` 已增长（不再是 0）

## BUG-03-后续: 流量统计不准确（缓存失效）

> 发现时间: 2026-03-20 13:40
> 影响节点: PO0 (111.229.215.107)
> 影响面板: 38.165.47.12

### 问题描述
面板显示的已用流量（100.06 KB）与实际 nft counter 统计值（约 218 KB）不一致，用户反馈"红色框的部分和实际使用的流量对不上"。

### 根因分析
nft 规则重置后 counter 归零，但缓存文件 `/var/lib/fork-nft/nft-flow-exporter.json` 保留着旧值，导致：

1. 缓存值 > 当前 nft counter 值
2. delta = current - previous ≤ 0
3. 流量导出器认为"无新流量"，不上报

**数据对比**:
| 端口 | 转发 | nft counter | 数据库 inFlow | 差异 |
|------|------|-------------|---------------|------|
| 31000 | JP-CO | 137,541 B | 62,396 B | 75,145 B |
| 31001 | HK-Jinx | 85,019 B | 27,659 B | 57,360 B |
| 12071 | Boil HKT | 512 B | 512 B | 0 B |

### 修复方案

#### 1) 删除缓存文件
```bash
ssh root@111.229.215.107
rm -f /var/lib/fork-nft/nft-flow-exporter.json
```

#### 2) 验证 timer 运行
```bash
systemctl status nft-flow-exporter.timer --no-pager -l
journalctl -u nft-flow-exporter.service -n 20 --no-pager
```

#### 3) 手动触发上报（可选）
```bash
python3 /usr/local/bin/nft-flow-exporter.py \
  --panel-base "http://38.165.47.12:6365" \
  --panel-user "jack" \
  --panel-password "lpsz800203" \
  --panel-secret "13df4ca9916a5f1ae601381cf97a42b8"
```

### 线上验证
- ✅ 缓存已删除并重新初始化
- ✅ nft-flow-exporter.timer 正常运行（每10秒）
- ✅ 流量开始正常上报

### 预防措施
当重新部署 nft 规则或重启节点时，应：
1. 停止 nft-flow-exporter.timer
2. 删除缓存文件
3. 重新部署规则
4. 启动 timer
