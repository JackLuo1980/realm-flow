# 兴业银行智能贯标项目-领导汇报摘要

## 一、项目定位
本项目是面向全行开发人员的“数据字典 + 贯标”智能辅助项目，不是泛化的数据治理平台建设，也不建议建设独立 AI 门户。项目目标是在不改变现有数据字典主入口和兴业自研单体贯标主流程边界的前提下，将智能贯标能力嵌入现有数据字典系统，帮助开发人员更快找数、找标准、避免重复建标，并辅助标准管理员提升标准评审与维护效率。

## 二、要解决的核心问题
- 开发人员找表、找字段、找标准效率低，依赖人工问询和经验传递
- 已有数据标准和字段位置分散，复用成本高
- 标准新增、标准变更和评审仍较依赖人工判断，重复标准和不规范标准难以及时识别
- 现有数据字典虽有基础，但尚未沉淀成可用于智能检索与智能推荐的知识库
- 接入系统存在贯标率考核要求，但当前缺少系统级覆盖分析、缺口识别和整改辅助能力，导致补标工作常常集中突击、质量不稳定

## 三、一期建设重点
- 建设标准知识库与文档知识库
- 打通现有数据字典系统与自研贯标单体系统
- 以前台内嵌、后台服务化方式接入，不新增独立门户
- 建设四类核心能力：
  - 智能取数
  - 标准推荐
  - 重复标准检测
  - 智能纠错
- 增加贯标率分析与整改辅助能力
- 建设审核闭环、反馈回流、运营看板

## 四、面向用户的直接价值
- 对开发人员：通过自然语言直接查询表、字段、标准和所在系统，降低找数成本
- 对标准管理员：提高推荐、判重、纠错效率，减少重复审核和低价值人工比对
- 对科技管理层：形成可量化的提效指标，如智能取数命中率、定位时长下降、标准推荐采纳率、接入系统贯标率提升与整改闭环率

## 五、技术路线
- 展现形态：嵌入现有数据字典系统，复用现有登录、菜单、权限和页面框架
- 应用技术体系：前端遵循现网 Vue 体系，后端采用 Java + Spring Boot，结合现有单体架构进行模块化改造
- 模型能力：客户自带私有化部署 `Qwen3`、`DeepSeek3`
- 数据库：当前支持 `openGauss`、`TDSQL`，后续兼容商用版 `GaussDB`
- 检索方案：关系库 + 全文检索为主，向量能力按最小必要原则引入
- 知识库路线建议：
  - 一期快速落地：`RAGFlow + Java 自研业务层`
  - 长期可控路线：`Spring AI + Java 自研知识服务`

## 六、实施建议
- 一期周期建议：约 4-5 个月
- 一期工作量建议：约 50-72 人周
- 试点方式：先聚焦“数据字典 + 贯标”的通用场景，不绑定单一业务条线

## 七、领导关注的关键结果
- 是否真正提升开发人员找数效率
- 是否降低重复建标和低质量建标
- 是否能够形成可复用、可审计、可持续运营的标准知识底座
- 是否具备后续扩展到更多标准化场景的能力

## 八、建议结论
本项目建议按“数据字典内嵌、知识库先行、规则约束、模型增强、人机协同、私有化部署、信创兼容”的路线推进。一期目标不是追求炫技，而是先把开发人员高频使用的智能取数与贯标辅助能力做实，形成可见价值和可量化成效。
