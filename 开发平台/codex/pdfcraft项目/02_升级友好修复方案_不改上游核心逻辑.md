# 升级友好修复方案（不改上游核心逻辑）

日期：2026-03-19
原则：
- 不 fork 大改
- 不改 OCR 业务算法
- 仅做可回滚的部署层增强与轻量接入

## 方案目标
把 OCR 的外部依赖改为“本站本地优先”，避免用户浏览器直连第三方 CDN 导致随机失败。

## 方案设计

### 变更A：新增本地静态镜像目录（部署层）
新增（示例）：
- `/tesseract/worker.min.js`
- `/tesseract-core/*`
- `/tessdata/eng.traineddata.gz`
- `/tessdata/chi_sim.traineddata.gz`

说明：这是新增目录，不改上游组件结构，后续升级时只需复用这层静态资源策略。

### 变更B：OCR 初始化时指定路径（小改，低冲突）
将 OCR worker 初始化改为本地路径优先：

```ts
const worker = await Tesseract.createWorker(languages.join('+'), 1, {
  workerPath: '/tesseract/worker.min.js',
  corePath: '/tesseract-core',
  langPath: '/tessdata',
});
```

建议实现成“可配置覆盖”，例如环境变量控制，避免后续上游升级冲突。

### 变更C：保留回退（本地失败再走 CDN）
若本地资源缺失，回退至官方 CDN，避免单点故障。

## 为什么这套方案升级友好
1. 主要是部署资产增强，不重写 OCR 流程。
2. 代码改动可收敛在 OCR 初始化点（1 处）。
3. 上游升级时冲突面小，只需要复核该初始化点。
