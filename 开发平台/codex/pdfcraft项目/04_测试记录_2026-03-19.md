# 测试记录（2026-03-19）

## 测试范围
围绕 OCR 失败链路做可执行验证（网络、依赖加载、站点头部、路径可达）。

## 已执行结果

### 1) 站点基础响应头检查
命令：
```bash
curl -I -L https://pdf.lottery.eu.org/zh/
```
结果：
- HTTP 200
- 存在 `Cross-Origin-Opener-Policy: same-origin`
- 存在 `Cross-Origin-Embedder-Policy: require-corp`
- 存在 `Cross-Origin-Resource-Policy: cross-origin`

结论：跨域隔离头部正常。

### 2) pdf.js worker 路径检查
命令：
```bash
curl -I https://pdf.lottery.eu.org/workers/pdf.worker.min.mjs
curl -I https://pdf.lottery.eu.org/zh/workers/pdf.worker.min.mjs
```
结果：
- `/workers/pdf.worker.min.mjs` 返回 200
- `/zh/workers/pdf.worker.min.mjs` 返回 404

结论：worker 正常路径在根目录 `/workers/*`，不应拼 locale 前缀。

### 3) 浏览器内 Tesseract 初始化连通性检查
在页面执行：
- 动态加载 `tesseract.js@6.0.1`
- `createWorker('chi_sim')`

结果：初始化成功。

结论：当前环境下并非“必然失败”，更像用户侧网络/资源链路抖动导致的间歇问题，因此需要“本地静态优先”来提高稳定性。
