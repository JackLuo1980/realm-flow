# TG Exit Bot 实验节点预检设计

## 目标

只对“实验性节点”增加切换前预检，避免把 `tg-exit-bot` 切到会导致 Telegram 失联的坏出口。

## 范围

- 仅影响实验性节点的切换路径
- 稳定节点保持原有行为，不额外增加延迟
- 失败时自动回滚到稳定出口，不要求用户手动介入

## 行为

1. 用户选择实验性节点
2. Bot 先记录当前稳定出口
3. Bot 切换到候选节点
4. Bot 用短超时检查 Telegram API 可达性
5. 如果预检失败，自动回滚到原出口
6. 如果预检成功，保留切换结果

## 白名单

- `香港机房出口` 视为稳定出口
- 稳定出口不做预检，直接允许切换
- 预检只对实验性节点执行

## 失败处理

- 预检失败时返回明确提示
- 自动回滚后提示已恢复到原出口
- 不修改测速逻辑，因为测速已经移除

## 验收标准

- 切换实验节点时，坏出口不会长期卡住 bot
- 切换稳定节点时，体验不变
- 回滚后 `/nm` 能继续正常使用
